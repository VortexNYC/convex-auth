---
title: Migrating from WorkOS
description: Concept mapping and the import path from WorkOS AuthKit to convex-auth.
---

WorkOS sells you the authentication protocol surface — SSO, directory sync, the AuthKit hosted flow — while keeping user state in their cloud. convex-auth moves the same capability set into your Convex deployment. The component ships `migrate:*` writer mutations plus a `normalizeWorkosExport` normalizer (`@vortex-api/convex-auth/migrations`) that maps WorkOS User Management API payloads onto them; `scripts/migration-e2e/` in the repo is a working driver that seeds, pulls, normalizes, and applies against a scratch deployment.

## Concept mapping

| WorkOS                                      | convex-auth                                                                                                                      |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| AuthKit hosted sign-in                      | Drop-in auth pages — [UI components](./components)                                                                               |
| `getAuthorizationUrl()` + callback          | `signIn.social` / OAuth flow — [OAuth](./oauth)                                                                                  |
| Enterprise SSO (Okta, Entra, …)             | [Generic OAuth](./generic-oauth) — OIDC/OAuth2 only. **No SAML path today**; a SAML-only customer cannot migrate that connection |
| Users + identities                          | Users, identities, sessions in the `convexAuth` tables                                                                           |
| Organizations + memberships                 | [Organizations](./organizations) with roles and invitations                                                                      |
| API keys (machine auth)                     | [API keys](./api-keys) and [service principals](./service-principals)                                                            |
| WorkOS Events / webhooks                    | [Webhooks](./webhooks) — signed, with replay protection                                                                          |
| Session cookies via `@workos-inc/authkit-*` | Framework adapters — [Next.js](./nextjs), [TanStack Start](./tanstack-start)                                                     |
| Directory Sync (SCIM)                       | Not built today — [OIDC provider](./oidc-provider) covers the "your app as IdP" direction                                        |

## The cutover path

1. **Stand up convex-auth** in staging — [Quickstart](./quickstart). If you used WorkOS for SSO, configure each enterprise IdP under [Generic OAuth](./generic-oauth) and verify the provider accepts your new callback URLs (`https://<your-deployment>.convex.site/api/auth/callback/<provider>`).
2. **Export users** from the WorkOS API — `GET /user_management/users`, `/organizations`, `/organization_memberships`, and `/invitations`. WorkOS does not expose password hashes through its API (most AuthKit users authenticate via SSO or magic links anyway), so imported password users land on the reset path. If you request a hash export from WorkOS support, rows carrying `password_hash` + `password_hash_type: "bcrypt"` or `"argon2"` are imported as credentials instead — bcrypt digests lazily rehash to argon2id on first sign-in.
3. **Import users and orgs.** Feed the API payloads into `normalizeWorkosExport` — it derives org slugs (WorkOS has none), filters pending/inactive memberships, and turns pending invitations into invited seats. Apply the result with the component's `migrate:migrateUser` / `migrateAccount` / `migrateOrganization` / `migrateMembership` mutations (run via `convex run --component`, as the e2e driver does). Roles that don't exist in the destination catalog are created with empty permissions — grant scopes deliberately after cutover.
4. **Re-register SSO connections.** Each enterprise connection that speaks OIDC becomes a [Generic OAuth](./generic-oauth) config — a new client registration at the IdP, so plan lead time with your customers' IT teams before cutover. SAML-only connections have no target today.
5. **Cut over the client.** Replace the AuthKit SDK calls with the auth client (`useConvexAuthClient()` gives you `signIn.social`, `signOut`, and the rest; `useSession()` tracks auth state) — the [React guide](./react) maps the hooks.

## What does not migrate

- Active sessions and WorkOS session cookies.
- SCIM / Directory Sync — there is no equivalent today; HR-driven provisioning stays manual or moves to your own sync via the API.
- Audit Trails (WorkOS's hosted audit UI) — auth events land in your Convex tables instead, and [webhooks](./webhooks) can feed your own audit sink.
